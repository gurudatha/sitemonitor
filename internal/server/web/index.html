      Getting started with user jobs

      1. Upload the program: User jobs → Add job & programs → Upload program. Python (.py), Perl (.pl), PowerShell (.ps1), shell (.sh, .bash), batch (.bat, .cmd) or an executable. File names may contain letters, digits, . _ - (no spaces).
      2. Add the job on the same page: choose the program, type the arguments one per line, pick Every (interval) and For (how long, at most 24 hours for user jobs), and Where it runs.
      3. Check it: the job's page opens. Press Run now and read the output. It then runs on its own; past runs are under Results history.
      4. Keep it permanently: press Request merge. An admin can approve it into the admin's periodic activities (no 24-hour limit).

      Where can it run? The monitor servers are Linux. Scripts and Linux programs (built for Alpine / musl, or statically linked) run on the monitor server. Windows .exe, .bat and Windows PowerShell scripts must run on a remote server with OS Windows (Cygwin); an admin configures the credential and host key first.

      Schedules, limits and results

      Every1m, 2m, 5m, 10m, 15m, 20m, 30m, 60m, 1h, 2h, 4h, 6h, or once, when the server comes up
      For1h, 2h, 4h, 8h, 12h or 24h for user jobs (the window starts when the job is added or edited). Admin activities may have no end.
      TimeoutDefault 5m, at most 30m, never longer than the interval. On timeout the program and all its child processes are stopped.
      Exit code0 = OK 1 = WARN anything else = CRIT (the Nagios plugin convention). Two failures in a row open an incident.
      Outputstdout and stderr are kept (64 KB each per run) and shown on the job's page.
      EnvironmentA fresh empty working directory per run (also HOME and TMPDIR), PATH, LANG=C.UTF-8, and SITEMONITOR_JOB, SITEMONITOR_RUN_ID, SITEMONITOR_NODE. No other variables or secrets.
      ArgumentsAt most 32 arguments, each at most 1024 characters, no NUL characters.

      How arguments are passed

      • One line = one argument, exactly as typed. Spaces inside a line stay inside that argument. Leading and trailing spaces are kept. Empty lines are ignored (an empty argument is only possible through the API).
      • No shell is involved. Nothing is expanded or interpreted: $HOME, *.log, $(cmd), `cmd`, ; & | > and quotes all arrive as plain text. Do not add quotes or escapes: they would become part of the argument.
      • Remote Linux and Cygwin servers receive exactly the same arguments: SiteMonitor quotes each one safely for the remote shell.
      • Windows programs started through Cygwin receive them through Windows command-line rules; see the batch, PowerShell and .exe sections for the few characters to avoid.
      • Verified for Python, Perl and sh, locally and over SSH, with every example in the table below (automated test internal/jobs/args_test.go). The Windows notes follow Windows' documented rules; test Windows jobs with Run now.

      Python (.py, run with python3)

      Arguments typed in the form

      --url
https://shop.example/api?x=1&y=2
--max-ms=800
--label
Checkout "fast path" (EU)

      What the script receives

      sys.argv[1:] == [
  "--url",
  "https://shop.example/api?x=1&y=2",
  "--max-ms=800",
  "--label",
  'Checkout "fast path" (EU)',
]

      Script

      import argparse, sys, urllib.request, time

p = argparse.ArgumentParser()
p.add_argument("--url", required=True)
p.add_argument("--max-ms", type=int, default=1000)
p.add_argument("--label", default="")
a = p.parse_args()          # reads sys.argv[1:]

t = time.monotonic()
urllib.request.urlopen(a.url, timeout=10).read()
ms = (time.monotonic() - t) * 1000
print(f"{a.label}: {ms:.0f} ms")
sys.exit(0 if ms <= a.max_ms else 1)   # 1 = WARN
      • Negative values: argparse treats -5 as an option. Use --threshold=-5, or put -- on its own line before positional values that start with -.
      • Arguments are already Unicode str; nothing to decode.
      • Exit with sys.exit(0|1|2); an uncaught exception exits with 1 (WARN). Use sys.exit(2) for CRIT.

      Perl (.pl, run with perl)

      Arguments typed in the form

      --path
C:\Logs\app *.log
--pattern
ERROR|FATAL
--days=7

      What the script receives

      @ARGV = ('--path', 'C:\Logs\app *.log',
         '--pattern', 'ERROR|FATAL', '--days=7')

      Script

      use strict; use warnings;
use Getopt::Long;

my ($path, $pattern, $days) = ('', '', 1);
GetOptions('path=s' => \$path, 'pattern=s' => \$pattern,
           'days=i' => \$days) or exit 2;

# $pattern is plain text from the job; use it as a regex on purpose,
# or quote it with \Q...\E to match it literally:
my $re = qr/$pattern/;
print "checking $path for $re (last $days days)\n";
exit 0;
      • Perl does not expand wildcards in @ARGV; use glob() yourself if you pass a pattern.
      • Non-ASCII arguments arrive as UTF-8 bytes: add use Encode; my @args = map { decode('UTF-8', $_) } @ARGV; if you need characters.

      Shell scripts (.sh with sh, .bash with bash)

      Arguments typed in the form

      /var/log/my app
*.log
$(rm -rf /)

      What the script receives

      $1 = /var/log/my app
$2 = *.log
$3 = $(rm -rf /)      # just text, never executed

      Script: always quote "$1" and "$@"

      #!/bin/sh
dir="$1"; pattern="$2"

# RIGHT: quoted, so spaces and * stay as given
for a in "$@"; do printf 'arg: [%s]\n' "$a"; done
find "$dir" -name "$pattern" -mtime -1 | head

# WRONG: unquoted $1 splits "/var/log/my app" into two words
#        and an unquoted $2 is expanded as a glob
# ls $1/$2

# never pass arguments through eval / sh -c "$1"
exit 0
      • SiteMonitor never interprets the arguments, but your script can: quote every expansion ("$var"), avoid eval, and use -- before arguments that could start with - (rm -- "$f").
      • Alpine's sh is BusyBox ash; use the .bash extension for bash features (arrays, [[ ]]).

      PowerShell (.ps1)

      Local and remote Linux: pwsh -NoLogo -NoProfile -NonInteractive -File script.ps1 <args>. Windows (Cygwin): powershell.exe … -ExecutionPolicy Bypass -File script.ps1 <args>. With -File, arguments are plain strings, never evaluated (no $env:, no sub-expressions).

      Arguments typed in the form

      -ComputerName
db-01.corp.local
-Services
Spooler,W32Time
-MaxAgeHours
6

      Binding in the script

      $ComputerName = 'db-01.corp.local'
$Services     = 'Spooler,W32Time'   # one string
$MaxAgeHours  = 6                   # converted to [int]

      Script

      param(
  [Parameter(Mandatory)] [string] $ComputerName,
  [string] $Services = '',
  [int]    $MaxAgeHours = 24
)
[Console]::OutputEncoding = [Text.Encoding]::UTF8
$names = $Services -split ','          # split lists yourself
$bad = foreach ($n in $names) {
  $s = Get-Service -Name $n -ErrorAction SilentlyContinue
  if (-not $s -or $s.Status -ne 'Running') { $n }
}
if ($bad) { "Not running: $($bad -join ', ')"; exit 2 }
"All running on $ComputerName"; exit 0
      • Named parameters: put -Name and its value on separate lines, or use -Name:value on one line. A line -Name value becomes one argument and will not bind.
      • Arrays: -File passes a,b,c as one string. Split it in the script (as above).
      • Switches: a line -Verbose or -Force works; to turn a switch off use -Force:$false on one line.
      • Arguments starting with - that are values (e.g. -5) can be mistaken for parameter names: use -Offset:-5.
      • Windows PowerShell 5.1 (powershell.exe) may strip or split embedded double quotes in arguments. Avoid " in values; for structured data pass Base64 and decode it: [Text.Encoding]::UTF8.GetString([Convert]::FromBase64String($Data)) | ConvertFrom-Json.
      • Exit codes: exit 0/1/2. An unhandled terminating error exits with 1 (WARN); use $ErrorActionPreference='Stop' plus try { … } catch { exit 2 } for CRIT.

      Windows batch (.bat, .cmd, remote Windows only)

      Started as cmd.exe /c script.bat <args>. cmd.exe re-reads the command line, so some characters keep a special meaning even though SiteMonitor passes them safely.

      Safe arguments

      C:\Data\Reports
monthly report.xlsx
--keep=30
D:\Backup Folder

      Avoid in batch arguments

      &  |  <  >  ^      (command operators)
%NAME%  100%       (variable expansion)
!                  (with delayed expansion)
"embedded quotes"

      Script

      @echo off
setlocal
rem %~1 removes surrounding quotes added for spaces
set "SRC=%~1"
set "FILE=%~2"
if not exist "%SRC%\%FILE%" (
  echo missing: %SRC%\%FILE%
  exit /b 2
)
echo found %SRC%\%FILE%
exit /b 0
      • Always read arguments as "%~1" (quoted, with ~) so paths with spaces work.
      • If you need URLs, regexes or any of the characters above, write the job in PowerShell or as an .exe instead of a batch file.
      • End with exit /b <code>; without it the exit code of the last command is used.

      Executables (.exe on Windows, native Linux programs)

      • Linux programs (no extension, or any extension not listed above) are started directly with the arguments as an array (argv): every character in the table works. Build them for Alpine/musl or statically (Go: CGO_ENABLED=0; Rust: --target x86_64-unknown-linux-musl).
      • Windows .exe through Cygwin: Cygwin turns the arguments into a Windows command line using the standard Microsoft quoting rules. Programs that read arguments the normal way (main(argc, argv), wmain, .NET string[] args, Go os.Args, Python) receive them exactly, including spaces, quotes and backslashes.
      • A few programs parse the raw command line themselves (some installers, msiexec, robocopy options); test them with Run now.
      • Paths: Windows programs need Windows paths (C:\Data), not Cygwin paths (/cygdrive/c/Data). Cygwin does not translate arguments for native programs.

      Arguments typed in the form

      /scan
C:\Program Files\Vendor\data
/threshold:90
/tag:"nightly run"

      What a C# / .NET program receives

      args[0] = "/scan"
args[1] = "C:\Program Files\Vendor\data"
args[2] = "/threshold:90"
args[3] = "/tag:\"nightly run\""   // quotes are part of the value

      Arguments in API calls (agents, scripts)

      In the API, args is a JSON array of strings. JSON has its own escaping: backslash becomes \\, double quote becomes \", tab \t, newline \n. Everything else is written as is.

      Program should receiveJSON in "args"
      C:\Program Files\App"C:\\Program Files\\App"
      \\server\share"\\\\server\\share"
      say "hi""say \"hi\""
      ^\d+(\.\d+)?$"^\\d+(\\.\\d+)?$"
      {"k": "v"}"{\"k\": \"v\"}"
      it's $HOME & *.log"it's $HOME & *.log" (no escaping needed)

      bash / WSL: keep the JSON in a file (no shell quoting problems)

      cat > job.json <<'JSON'
{
  "name": "win-report",
  "binary": "report.exe",
  "args": ["/out", "C:\\Reports\\daily report.csv", "/filter:status=open&team=ops"],
  "schedule": {"type": "interval", "every": "1h", "run_for": "12h"},
  "target": {"host": "10.20.0.15", "port": 22, "os": "windows-cygwin", "credential": "win-cygwin"}
}
JSON
curl -sk -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
     --data-binary @job.json https://monitor:8080/api/jobs

      PowerShell: build an object and let ConvertTo-Json escape it

      $job = @{
  name     = 'disk-check'
  binary   = 'disk.py'
  args     = @('--path', 'C:\Data\My Files', '--pattern', '*.tmp', '--note', 'it''s "urgent"')
  schedule = @{ type = 'interval'; every = '15m'; run_for = '8h' }
}
$body = $job | ConvertTo-Json -Depth 5
Invoke-RestMethod -Method Post -Uri https://monitor:8080/api/jobs `
  -Headers @{ Authorization = "Bearer $token" } -ContentType 'application/json' -Body $body
# PowerShell single-quoted strings: no escaping except '' for a single quote
# (PowerShell 7: add -SkipCertificateCheck for the demo certificate)

      Python agent

      import requests   # json= escapes everything correctly
requests.post("https://monitor:8080/api/jobs", verify="ca.crt",
  headers={"Authorization": f"Bearer {token}"},
  json={"name": "regex-check", "binary": "grep.pl",
        "args": ["--pattern", r"^\d+(\.\d+)?$", "--file", r"C:\Logs\app.log"],
        "schedule": {"type": "interval", "every": "30m", "run_for": "24h"}})

      API for agents

      • Every feature has an endpoint. The machine-readable description is at /api/openapi.json (OpenAPI 3.1, with the role each call needs).
      • An admin creates a token for the agent: POST /api/tokens {"name":"my-agent","role":"operator"}. The agent sends Authorization: Bearer <token>.
      • Useful calls: GET /api/summary, GET /api/status, GET /api/incidents?status=open, GET /api/events, POST /api/jobs, POST /api/jobs/{id}/run?wait=true, GET /api/jobs/runs.
